Test Suite · Overview
The test suite is the user workflows, made runnable
Every user workflow declares, node by node, what data enters, what processing happens, and what data exits — and its expected final data-out is locked as a golden assertion. This page turns each of those workflows into an executable test you can drive in real time: pick an input (a preset or your own), run it, and watch the diagram light up node by node while two panels stay in sync — on the left what the user sees, on the right the actual data-in / processing / data-out at that node, threaded end-to-end so each node's output is visibly the next node's input. Every run is recorded, so there is a permanent log per workflow.

One source, three faces

The diagram, the per-node breakdown, and the executable test all come from a single machine-readable map — docs/workflows.json — generated from the project's own spec (Phase 4 workflow derivation + Phase 5 test mapping). The prose version of the same map lives on the page; the pass/fail of the immutable harness lives on Eval. This page is the runnable face that ties them together — it is generated dynamically per project, not hand-authored.

Test Suite · How it works
The contract behind the theater
A node in workflows.json carries both its declared contract (in / proc / out — the same prose as the Users page) and an exec spec that runs a real, bounded command against the live build. The runner executes each node, threads its output into the next node's input, and streams the trace.

Bounded by construction

No node triggers a real /rapid-workflow build or spends money. For this project the execs are RAPID's own seconds-scale tools — ship-gate.sh (re-runs the eval harness), stub-scan.sh (scans the tree) — and reads of live state files (.rapid/STATE.json, TASKS.json, GAPS.json). For a built project, Phase 5 generates these execs to point at that project's own test / e2e commands and UI surfaces. The map is generated; the theater is generic.

Because each node runs a real command and asserts an exit code or a resolved value, a green run is derived from the current tree — not a remembered claim. A node that fails surfaces the real error in its data panel, never swallowed.

Agent-backed nodes: Codex tester + simulated operator

Codex is the tester; a guardrailed agent simulates the human

Test nodes (exec.kind: "codex") are run by Codex (the OpenAI Codex CLI) under a sandboxed codex exec with a strict JSON verdict schema {status, evidence, commands_run}. Codex actually runs the test (e.g. the ship gate) and returns an independent pass/fail with the evidence it observed — the writer is never the auditor. Role doc: 04-spec/agents/tester-codex.md.

Where a workflow needs a human at a gate (exec.kind: "human"), a simulated operator agent stands in so the gate can be dry-run end-to-end — with hard guardrails: it fails safe (defaults to hold, never rubber-stamps), decides only from cited evidence, runs read-only, and never approves anything destructive, irreversible, outward-facing, or that spends money / deploys — those force needs_real_human: true and a real person must own them. It is always labeled "operator (simulated)" and is never authorization for a real action. Role doc: 04-spec/agents/operator-sim.md.

Always runnable. Each agent node keeps a deterministic fallback, so with --agents off (or no Codex installed) the run still completes — the live ▶ Run uses Codex (--agents auto); the bulk republish uses the fallback to stay free.

Project Lifecycle E2E (WF-5). One suite is the acceptance test of the skill itself: it creates a new project (tools/new-project.sh), populates its docs from the project's own artifacts, builds the local app (Codex tester judges it), and deploys dev to a local/staging dir (the simulated operator approves the local deploy, but would hold a real cloud one) — asserting all three deliverables and writing .rapid/E2E.json. Driven by tools/lifecycle-e2e.sh; bounded (local, no paid services). The full multi-agent /rapid-workflow build + real cloud deploy is the opt-in live tier.
Run it yourself: python3 tools/workflow-runner.py --wf WF-1 --preset math-tutor  ·  --all runs every workflow  ·  --input '{"idea":"…"}' drives your own input  ·  --agents on|off|auto toggles Codex (default auto).
