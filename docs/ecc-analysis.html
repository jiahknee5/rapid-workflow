ECC is a 209k-star, cross-harness "operator system for agentic work" — skills, instincts, memory, security, research-first development, spanning Claude Code / Codex / Cursor / Gemini / Zed. Most of its surface is breadth we don't want; underneath it there is one idea worth stealing outright, two worth borrowing in part, and a lot we already do better for our narrower mandate.

Context · 01

ECC is a broad, multi-harness operator kit — wide, not deep on any one harness

Self-described as "the harness-native operator system for agentic work … not just configs. A complete system: skills, instincts, memory optimization, continuous learning, security scanning, and research-first development." It ships adapters for ~12 agent harnesses and ~12 language ecosystems, an MIT core, and a paid ECC Pro / GitHub-App tier.

Its guide table is the clearest statement of what it actually teaches: token optimization, memory persistence (hooks that save/load context across sessions), continuous learning (auto-extract patterns into skills), verification loops (graders, pass@k), parallelization (worktrees, "cascade"), and subagent orchestration.

Context · 02

Separate the marketing from the transferable substance

ECC is heavily marketed — inflated star counts, sponsor walls, a $19/seat Pro tier, 12 translated READMEs. Read past that. Rapid is deliberately Claude-Code-native; ECC's biggest selling point (cross-harness portability) is a non-goal for us. The transferable substance is narrow but real:

  • A continuous-learning pipeline with a maturation ladder — the one genuinely novel thing relative to us.
  • A richer verification vocabulary — graders + pass@k for non-deterministic output.
  • A disciplined token-optimization habit.

Everything else is either something we already have, or something we intentionally don't want.

Fit · 05

What we should explicitly not take

  • Cross-harness portability. Rapid is Claude-Code skills + hooks by design; multi-harness adapters add surface and dilute the thesis.
  • Memory architecture. We have a robust one; ECC's isn't better, just different.
  • The dashboard / worktree / orchestration patterns. Ours are equivalent and tighter (verified isolation, five-lead model, skill-generated surfaces).
  • The marketing apparatus. Stars, tiers, sponsor walls — not signal.
★ Integrate · the big one

Steal the maturation ladder: observation → scored instinct → graduated skill

Rapid's single best differentiator is the compound claim — "the loop is the product; each build makes the next smarter." Today that's realized as LEARNINGS.md + P10→P0: manual (the agent must remember to write a learning) and flat (a learning is written or not; nothing graduates). ECC's Continuous Learning v2 supplies the missing mechanism — a promotion ladder with scoring:

Observation.rapid/observe/*.jsonl
Already captured mechanically — every WRITE / ERROR / DECIDE / LOOP_* event the hooks emit. Nothing new to instrument; the raw material is the event stream we already ship.
▼ /learn extracts
Scored instinct.rapid/INSTINCTS.json
A lightweight heuristic with a hit-count + confidence (error→fix patterns, debugging moves, library quirks). The tier we're missing between "noted once" and "codified skill."
▼ recurs across builds, score clears a bar
Candidate skilldraft in skills/
An instinct that keeps proving out graduates into a real skill — the compound loop made mechanical, not aspirational.
▼ reviewed at a gate
Durable skillskills/<name>/SKILL.md
Promoted, named, product-agnostic — and now it makes every future build smarter, which is the whole thesis.
Why it fits us so wellWe already have the two inputs ECC's pipeline needs — the observe event stream (mechanical logging) and MEMORY.md. We'd only be adding the scoring + graduation on top. ECC built this for portability; we'd build it for compounding.
Integrate · 06

Add a /learn skill — extraction becomes mechanical, not hoped-for

ECC's /learn mines a finished session for error-resolution patterns, debugging techniques, and workarounds, then writes candidate guidance. Our version would read the build's own observe stream + MEMORY.md (richer than a raw transcript) and emit scored instincts into .rapid/INSTINCTS.json — the entry point to the ladder above.

  • Fixed: the extraction taxonomy (error→root-cause→fix; tool combos; library quirks; what-worked) and the scoring contract.
  • Dynamic: the patterns themselves, mined from this build.
  • Composes with: /refine (keep-or-revert) and the P8 gap loop — a gap that recurs becomes an instinct becomes a skill.
HonestyThis is the one place we're genuinely behind: our learning capture is voluntary. Making it a skill wired to the (already-mechanical) event stream removes the "did the agent remember" failure mode — the same writer-≠-auditor logic we apply to logging, applied to learning.
Integrate · 07

Borrow a grader taxonomy + pass@k for non-deterministic output

Our verification is binary completeness — untouched_functions == 0 — which is exactly right for structural coverage. It's too coarse for AI-output projects, where "did it pass" isn't yes/no. ECC's evaluator (GAN-style candidate-vs-verifier, RAG-backed, with grader types and pass@k) is the vocabulary /test-theater and /refine lack for stochastic surfaces.

  • Add grader types (exact / rubric / model-graded / pass@k) to a node's eval contract — scoped to AI-feature builds.
  • Keep the immutable-harness invariant; the grader is just a richer assertion than ==.
Integrate · 08

Honorable mention: a token-optimization discipline

We already route models (panels → Sonnet, code → Opus) and have the cost breaker. ECC's systematic habits — prompt slimming, background processes, per-task model selection — could sharpen the panel/lead routing and tighten the cost story. Low–medium value; we mostly have the bones.

Decision · 09

Recommendation — build one thing, borrow one, ignore the rest

BuildThe maturation ladder + a /learn skill (§★, §06). It's the highest-leverage thing ECC has that we lack, and it turns our best differentiator — compound learning — from a slogan into a mechanism, reusing the observe stream + MEMORY.md we already ship. Shape: skills/learn/ → .rapid/INSTINCTS.json (scored) → graduate to skills/ at a gate.
Borrow (follow-on)Grader taxonomy + pass@k (§07) into the eval / /test-theater / /refine layer — only for non-deterministic / AI-output builds.
IgnoreCross-harness adapters, ECC's memory, its dashboard/orchestration patterns, and the marketing. We have equivalents or better, scoped to a tighter mandate.

Net: ECC validates several of our bets (eval-first, worktrees, observability, learning-as-product) and surfaces exactly one capability gap worth closing — the promotion path from observation to skill. Worth a single, well-scoped PR; not worth chasing its breadth.
