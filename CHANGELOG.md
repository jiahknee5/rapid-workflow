# Changelog

All notable changes to Johnny's AI Build Workflow are documented here.

## [0.6.0] — 2026-06-07

### Changed
- **Renamed FORGE → RAPID throughout.** `/forge` → `/rapid-workflow` (with a `/workflow` alias), `.forge/` → `.rapid/` state directory, and every skill, hook, tool, template, and doc updated. The repo is `rapid-workflow`; the methodology is RAPID.
- **P6 build model: 3-terminal architecture → five-lead build team.** Five named lead agents — planner · coder · tester · reviewer · watchdog — each in its own long-lived terminal over claude-peers, fanning out ephemeral subagents as the parallel muscle. Tracks scale the team: full (5 leads) / fast (planner+coder+reviewer+watchdog) / tiny (all-subagent under the planner).
- **Expert panels expanded to five fixed areas** — Business · Technical · Design · SME · Users (was a single domain-selected set; adds a dedicated Design panel).
- Compound Engineering capabilities woven into the orchestrator grew from 7 to 15.
- Retired the flat methodology deck in favor of the Skills Atlas (archived, not deleted).

### Added
- **`/expert-panel` skill** — builds each of the five areas as 1st/2nd/3rd-order rosters (Practitioners → Shapers & Critics → Outsiders & Long-horizon), then pares to a working panel via an explicit rubric (composition rule ≥3 / ≥2 / ≥1). Named frameworks per area (Five Forces, JTBD, Test Pyramid, STRIDE, Double Diamond, Nielsen, Kano); Business capital lenses (founder / VC / PE / corporate C-suite / advisor); panel observability to `03-panels/roster.json`. Maps to the four risk lenses (Desirability / Feasibility / Viability / Legitimacy). Generic by construction — names no product.
- **`/refine` skill** — goal-directed propose → measure → keep-or-revert loop (Karpathy's autoresearch, generalized), used by the P8 gap loop so only improvements survive.
- **P5c: Mockups & Prototype phase** — hi-fi UI mockups + a clickable prototype approved at G2 before any build begins.
- **Function-level test acceptance (P7)** — every function on a page must be touched and considered in the test flows (`untouched_functions == 0`).
- **Planning-alignment lock at G2 + amendment protocol** — the raw PRD is frozen; the enhanced PRD becomes a versioned register; `tools/trace-check.sh` is a fail-closed traceability gate (every requirement → a spec section or `[OUT OF SCOPE]`; every screen → a requirement).
- **Per-PR alignment/quality checklist** — `templates/PR-CHECKLIST.md` + `.github/pull_request_template.md` (trace to PRD/spec, honor the panels, Constitution + pillars, quality).
- **Skills Atlas (Atlas v2 "Constellation" dark theme)** — per-phase pages generated by `tools/atlas-skills-gen.py`, embedding verbatim skill text per phase/gate.
- **Unified cross-surface navigation** — `docs/rapid-nav.js` gives one header across the Atlas, Build & Observatory, Test Suite, Documentation, Architecture, and Workflow.
- **`tools/rapid-team.sh`** — stands up the five-lead build team (tmux, or `--cursor` for VS Code tasks).
- **Workflow Test Theater + project-lifecycle E2E suite** — each user workflow is a runnable, recorded test driven by `docs/workflows.json`.

## [0.5.0] — 2026-05-27

### Added
- 3-terminal architecture for RAPID Phase 6 — orchestrator, supervisor, watchdog as persistent tmux sessions with claude-peers messaging (12 message types)
- Compound Engineering integration (7 capabilities from [Every Inc. CE plugin](https://github.com/everyinc/compound-engineering-plugin)):
  - Tiered multi-agent code review (5 parallel specialized reviewers with confidence gating)
  - Compound learning capture (`.rapid/LEARNINGS.md` — each build makes the next one smarter)
  - Document review agents at gates G0/G1/G2 (feasibility, scope guardian, coherence, adversarial)
  - Product Pulse (P10 — post-ship monitoring reports in `docs/pulse-reports/`)
  - Session intelligence for crash recovery
  - Structured debug protocol (reproduce → trace → hypothesis → test-first fix)
  - Optimization loops in P8 (parallel experiments, measure, keep best)
- Live observability dashboard (`rapid-observe.py` + `rapid-dashboard.html`) with agent topology graph, event stream, context estimation
- P1b: PRD Decomposition phase with G0: Enhanced PRD Review human gate
- McKinsey aesthetic + plain-English-first pattern applied to all documentation templates

### Changed
- Pipeline expanded from 10 phases / 3 gates to 12 phases / 4 gates (P1b + G0 + P10)
- Phase 6 restructured into P6a–P6e sub-phases (terminal setup, build loop, watchdog loop, monitoring, shutdown)
- Code review upgraded from single reviewer to tiered multi-agent review (5 specialized reviewers)
- Gap loop (P8) expanded with optimization loop for MEDIUM/LOW gaps
- Watchdog upgraded from event-triggered to persistent tmux terminal
- Smoke test ownership moved from orchestrator to supervisor

## [0.4.0] — 2026-05-27

### Added
- `/rapid-workflow status` command — structured terminal dashboard showing phase, agents, tasks, safety, alerts, cost
- Agent heartbeat protocol — `HEARTBEAT.json` updated every 5m during P6 with per-agent status, task, progress metrics, test counts, blocker info
- Enforced `claude-peers set_summary` — mandatory on spawn + on status change, with specific format: `[RAPID {role}] {status}: {description}`
- Stall detection tightened from 15m silence to 10m stale heartbeat
- `TEST_RESULTS.md` and `P6_EXIT.json` added to state files table

### Fixed
- 6 gap fixes from autonomous build test (applied externally):
  - Gap 1: Reference project protocol — spec is authority, reference is pattern guide
  - Gap 2: Smoke test mandatory — orchestrator runs build/test directly via Bash
  - Gap 3: Code review mandatory — P7 blocked until all tasks have APPROVE verdict
  - Gap 4: Secret scanning — grep for credentials after every agent return
  - Gap 5: Phase 7 unambiguous — "Execute via Bash, not a file audit"
  - Gap 6: P6_EXIT.json enforcement — STATE.json blocked until all assertions pass
